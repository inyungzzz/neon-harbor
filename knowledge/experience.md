# 開發經驗

## 用有上限的任務行動檔案保留分支後果

- **經驗：** 若任務卡只顯示目前委託，前往下一段後玩家便無法回看先前作出的選擇。將每次完成結果以純資料追加到存檔，並用 DOM `textContent` 呈現，能保留敘事脈絡而不把存檔文字當成 HTML；限制紀錄數量也可避免本機資料無限成長。
- **本次使用：** 新增 `missionHistory`，記錄任務名稱、選項、結果與結算後的遊戲時間；畫面按最近完成順序顯示最多 50 筆。既有存檔沒有此欄位時，讀取流程會以空清單補齊。
- **未來適用範圍：** 適用於單機互動故事的任務歷程、對話選擇和活動紀錄。若紀錄需要篩選、分頁或跨裝置同步，應再設計版本化資料格式與遷移，而非只擴張單一陣列。

## 讓任務解鎖提示跟隨任務資料更新

- **經驗：** 新增任務後，固定文案容易讓已解鎖或已完成的章節仍顯示過時提示。依任務索引、完成狀態與任務清單長度集中計算提示，可讓擴充內容時畫面狀態保持一致。
- **本次使用：** 新增第四份河岸委託，並在任務渲染時呈現首份待解鎖、後續委託可接取、新委託已解鎖或本章完成等文案。
- **未來適用範圍：** 適用於順序解鎖的任務章節與教程步驟。若加入可選支線或多條故事線，應由任務狀態模型提供解鎖狀態，不要繼續堆疊索引條件。

## 靜態 Web 遊戲的漸進式進度模型

- **經驗：** 單一任務原型很快能驗證操作，但若完成後只顯示「已完成」且沒有下一步，遊戲循環會中斷。把任務內容抽成資料清單，並讓 `missionIndex`、完成狀態與結果文字進入同一份存檔，就能用少量原生 JavaScript 延伸故事，而不用引入框架或後端。
- **本次使用：** 將一個委託擴成三段依序解鎖的任務線；每段有獨立選項、金錢、名聲及警方熱度結果，完成後明確提供下一個委託入口。
- **未來適用範圍：** 適用於純前端互動故事、教學原型、小型任務板與不需要即時多人同步的單機進度。當任務數量、分支或存檔結構變複雜時，再考慮拆分資料模組或加入版本遷移。

## 保留瀏覽器存檔的安全演進

- **經驗：** 新增狀態欄位時，以預設值合併既有 `localStorage` 資料，並對數值範圍做限制，可讓舊存檔在增加玩法後繼續讀取；重設操作則應只重設遊戲存檔，不影響其他網站資料。
- **本次使用：** 在既有存檔上新增任務索引與委託結果，沿用原本金錢、名聲、熱度及地圖位置，並限制任務索引與警方熱度的有效範圍。
- **未來適用範圍：** 適用於任何本機存檔逐步增加欄位的原型。若未來需要改變欄位含義、跨裝置同步或保存大量玩家資料，應加入明確的存檔版本與遷移流程。

## 將可重玩活動與主線分開

- **經驗：** 重複挑戰若直接改動主線任務索引，會讓玩家進度和活動次數互相干擾。把活動狀態（進行中、次數）放在獨立欄位，並在報名時先扣成本、完成路線後結算獎勵，可以同時保持循環清楚與收益平衡。
- **本次使用：** 新增港區兜風挑戰，報名費 $100，完成後可選穩定路線或高熱度捷徑；活動可重玩，且存檔不覆蓋主線進度。
- **未來適用範圍：** 適用於競速、送貨、街區委託等可重玩的單機活動。若加入倒數、碰撞或排行榜，再把活動拆成獨立狀態機與計時流程。

## 讓地圖移動觸發可收集物

- **經驗：** 網格式地圖的探索回饋可以直接綁在格子座標；駕駛若一次跨多格，需逐格處理中間座標，否則玩家可能越過收集點而無法取得。
- **本次使用：** 在三個街區座標放置港灣印記，步行或駕車經過都能收集；收藏清單、獎勵與名聲一併儲存在本機。
- **未來適用範圍：** 適用於地圖尺寸固定、移動以格子為單位的 Web 原型。若地圖改為連續座標或大型區域，改用碰撞／範圍判斷，避免逐格遍歷。

## 用一次性升級建立資源回饋

- **經驗：** 任務收入若沒有長期用途，資金狀態很快只剩數字。一次性、可見且能改變操作的升級，可把收入轉成可理解的成長；購買按鈕必須反映現金門檻與已安裝狀態，避免重複扣款。
- **本次使用：** 支付 $900 取得永久引擎調校，駕車步數由每次 2 格提高到 3 格；升級存入同一份本機存檔。
- **未來適用範圍：** 適用於單機原型中的車輛、裝備或藏身處升級。若升級有多階段、互斥分支或需要退款，再改用明確的升級資料表與購買交易紀錄。

## 確保移動觸發獎勵後同步更新 HUD

- **經驗：** 若移動事件可以直接增加金錢、名聲或收藏數，光重繪地圖會讓畫面上的 HUD 暫時落後於已存檔狀態。移動完成後要一起更新狀態列與地圖；簡短的狀態模擬可抓出這類跨元件問題。
- **本次使用：** 冒煙檢查發現拾取印記後計數器未即時更新；將資源與收藏計數抽成共用 `renderStats()`，讓一般移動和其他操作共用同一套更新邏輯。
- **未來適用範圍：** 適用於移動、碰撞、互動等同時改變遊戲狀態和 HUD 的事件。新增可改變狀態的操作時，至少檢查存檔、畫面數值、提示文字三者是否一致。

## 把人脈做成具體支援，而非只有分數

- **經驗：** 關係值只有在能改變玩法時才容易被玩家理解。讓特定角色的委託增加信任，並將門檻直接連到一項明確支援（折扣或免報名費），能讓支線選擇與資源系統形成回饋。
- **本次使用：** 阿哲信任達 2 點可把引擎調校由 $900 降至 $600；小葵信任達 2 點可免除兜風挑戰報名費。關係值上限 3 點並保存在本機。
- **未來適用範圍：** 適用於任務解鎖、商店折扣、情報或活動支援等單機 RPG／互動故事。角色數增加時，將關係、門檻與獎勵移入獨立資料表。

## 用輕量遊戲時間驅動日夜氛圍

- **經驗：** 純前端原型不必即時跑鐘，也能靠玩家行動推進遊戲時間。把時間放進存檔，並讓探索、任務與活動各自推進固定分鐘數，可以提供穩定、可重現的日夜轉換。
- **本次使用：** 步行每格推進 5 分鐘、駕車按移動步數推進、完成委託推進 60 分鐘、完成兜風挑戰推進 15 分鐘；時間跨過 06:00／18:00 時更新城市配色。
- **未來適用範圍：** 適用於回合式或事件式的靜態 Web 遊戲。若加入 NPC 即時行程、定時事件或多人同步，再改用統一遊戲時鐘服務。

## 讓任務入口依賴地圖抵達

- **經驗：** 若任務選項在任何時候都可直接點選，地圖移動只是裝飾。把任務接取狀態與目前目的地分開保存，並在抵達標記後才顯示接案入口，能讓探索、任務敘事和玩家操作形成一個完整循環。
- **本次使用：** 三份委託分布在不同網格座標；抵達當前標記並接案前隱藏選項，接取後才顯示不同處理路線。
- **未來適用範圍：** 適用於小型地圖、固定目標點的任務原型。若目標可動、任務有多階段或多人共同接取，應抽成任務狀態機與目的地資料。

## 讓風險恢復也需要位置與時間

- **經驗：** 若降低通緝熱度的按鈕可在任何地方即時使用，玩家不需要利用地圖或承擔等待成本。把恢復條件連到安全點並消耗遊戲時間，會讓高風險選擇產生一個短而明確的後續行動。
- **本次使用：** 玩家回到港區入口（安全點）後，花 30 遊戲分鐘可降低 1 級警方熱度；不在安全點時按鈕顯示返回提示並停用。
- **未來適用範圍：** 適用於單機任務原型中的通緝、疲勞或資源恢復。加入多個安全屋或警力追逐後，再將安全點與恢復規則資料化。

## GitHub Pages 初次部署順序

- **經驗：** GitHub Pages 必須先啟用並指定 GitHub Actions 為來源，之後部署工作流程的 `configure-pages` 才能取得 Pages 設定。若 workflow 在 Pages 啟用前觸發，第一次執行可能因找不到 Pages site 而失敗；啟用後重跑即可。
- **本次使用：** 先建立公開儲存庫並推送，再以 Pages API 設定 `build_type: workflow`，最後重新觸發 Actions 並確認網站回應。
- **未來適用範圍：** 適用於新 GitHub 儲存庫第一次設定 Pages；後續只需推送 `main`，不必重複設定。若上傳 artifact 成功但 deploy step 找不到 artifact，先查 Actions 執行紀錄並重跑，以區分暫時性服務問題與 workflow 設定錯誤。
