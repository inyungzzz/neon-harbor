# 開發經驗

## 靜態 Web 遊戲的漸進式進度模型

- **經驗：** 單一任務原型很快能驗證操作，但若完成後只顯示「已完成」且沒有下一步，遊戲循環會中斷。把任務內容抽成資料清單，並讓 `missionIndex`、完成狀態與結果文字進入同一份存檔，就能用少量原生 JavaScript 延伸故事，而不用引入框架或後端。
- **本次使用：** 將一個委託擴成三段依序解鎖的任務線；每段有獨立選項、金錢、名聲及警方熱度結果，完成後明確提供下一個委託入口。
- **未來適用範圍：** 適用於純前端互動故事、教學原型、小型任務板與不需要即時多人同步的單機進度。當任務數量、分支或存檔結構變複雜時，再考慮拆分資料模組或加入版本遷移。

## 保留瀏覽器存檔的安全演進

- **經驗：** 新增狀態欄位時，以預設值合併既有 `localStorage` 資料，並對數值範圍做限制，可讓舊存檔在增加玩法後繼續讀取；重設操作則應只重設遊戲存檔，不影響其他網站資料。
- **本次使用：** 在既有存檔上新增任務索引與委託結果，沿用原本金錢、名聲、熱度及地圖位置，並限制任務索引與警方熱度的有效範圍。
- **未來適用範圍：** 適用於任何本機存檔逐步增加欄位的原型。若未來需要改變欄位含義、跨裝置同步或保存大量玩家資料，應加入明確的存檔版本與遷移流程。

## 將可重玩活動與主線分開

- **經驗：** 重複挑戰若直接改動主線任務索引，會讓玩家進度和活動次數互相干擾。把活動狀態（進行中、次數）放在獨立欄位，並在報名時先扣成本、完成路線後結算獎勵，可以同時保持循環清楚與收益平衡。
- **本次使用：** 新增港區兜風挑戰，報名費 $100，完成後可選穩定路線或高熱度捷徑；活動可重玩，且存檔不覆蓋主線進度。
- **未來適用範圍：** 適用於競速、送貨、街區委託等可重玩的單機活動。若加入倒數、碰撞或排行榜，再把活動拆成獨立狀態機與計時流程。

## 讓地圖移動觸發可收集物

- **經驗：** 網格式地圖的探索回饋可以直接綁在格子座標；駕駛若一次跨多格，需逐格處理中間座標，否則玩家可能越過收集點而無法取得。
- **本次使用：** 在三個街區座標放置港灣印記，步行或駕車經過都能收集；收藏清單、獎勵與名聲一併儲存在本機。
- **未來適用範圍：** 適用於地圖尺寸固定、移動以格子為單位的 Web 原型。若地圖改為連續座標或大型區域，改用碰撞／範圍判斷，避免逐格遍歷。

## GitHub Pages 初次部署順序

- **經驗：** GitHub Pages 必須先啟用並指定 GitHub Actions 為來源，之後部署工作流程的 `configure-pages` 才能取得 Pages 設定。若 workflow 在 Pages 啟用前觸發，第一次執行可能因找不到 Pages site 而失敗；啟用後重跑即可。
- **本次使用：** 先建立公開儲存庫並推送，再以 Pages API 設定 `build_type: workflow`，最後重新觸發 Actions 並確認網站回應。
- **未來適用範圍：** 適用於新 GitHub 儲存庫第一次設定 Pages；後續只需推送 `main`，不必重複設定。若上傳 artifact 成功但 deploy step 找不到 artifact，先查 Actions 執行紀錄並重跑，以區分暫時性服務問題與 workflow 設定錯誤。
